# 化学在线卡牌游戏 MVP 0 规则冻结表

本文档用于记录 MVP 0 已明确采用、暂缓或特别裁定的规则，并保留 MVP 0 建立时的历史边界。两份原始规则文档保持不变；本文只说明 MVP 0 的实现口径，不改写原始规则。

Phase 8 已通过独立的 `docs/PHASE8_CHARACTER_RULE_FREEZE.md` 显式解冻角色系统。该解冻只覆盖本文中“暂不实现角色、角色体力差异、角色摸牌规则和角色技能”的限制；7C、68 张普通实体卡池、`tableReference`、主动 DIY、`FIRE` / `statusWindow` 等其他 MVP 0 冻结规则继续有效。

## 一、原始规则来源

- `docs/rules/core-rules-v0.1.docx`：核心游戏流程、开局、实验周期、行动、伤害、状态、淘汰、胜负与响应基础规则。
- `docs/rules/ion-reaction-and-diy-manual-v1.0.docx`：离子用途、反应关系、DIY 构建、气体与化学效果含义。
- `docs/MVP_PLAN.md`：MVP 0 的功能范围、暂缓功能、特别裁定与当前实现规划。
- `docs/PHASE8_CHARACTER_RULE_FREEZE.md`：Phase 8 角色系统的正式冻结规则，仅覆盖角色相关历史限制。

## 二、规则解释原则

- 用户明确确认或明确授权修改的 MVP 0 裁定，覆盖原始规则书中对应条款。
- 未被明确修改的内容，继续按原始规则书执行。
- `core-rules-v0.1.docx` 主要定义核心流程；`ion-reaction-and-diy-manual-v1.0.docx` 主要定义化学关系与 DIY。
- 两份原始规则书彼此冲突、且未被用户明确裁定时，标记为待裁定，不得自行推断或静默选择。
- `docs/MVP_PLAN.md` 中的架构草案、开发计划或目录建议，不自动构成对原始规则的覆盖；只有明确标为已定案、特别裁定或规则冻结的内容才可视为规则变更。

## 三、MVP 0 已裁定规则

### 基础范围

- MVP 0 只支持本地双人、公开调试模式。
- MVP 0 建立时不实现角色、角色体力差异、角色摸牌规则和角色技能；该历史限制从 Phase 8 起仅按独立角色冻结文档显式解冻。
- 双方初始体力均为 10。
- 纠正“实验台起火”身份后，普通主牌堆不再包含该角色技能；普通实体 `CardInstance` 总数冻结为 68，不补回到 70，也不得用虚构化学牌填充。
- 每个实验周期 3 个实验轮次。
- 每名玩家每周期最多 1 次主动 DIY。
- 响应 DIY 在 MVP 0 中关闭。

### 关联出牌与场面基准牌

- 存活的 `activePlayer` 在 `mainAction` 可以进行“普通出牌”：选择 1 张自己手牌中与当前 `tableReference` 合法关联的实体卡，不需要 `targetPlayerId`。
- 当 `tableReference` 为空时，存活的 `activePlayer` 可在 `mainAction` 使用任意实体手牌建立首张场面基准牌；可走“执行效果”或“普通出牌”路径，且该首张出牌不视为额外的“自由出牌次数”。
- 当 `tableReference` 非空时，`mainAction` 中从手牌打出的实体卡必须与 `tableReference` 关联；该限制同时适用于普通出牌路径和酸碱攻击、`SO2`、`FIRE`、`O2` 等执行实体主行动效果路径。
- 不关联时不得出牌、不得结算、不得弃牌、不得更新 `tableReference`、不得推进回合。
- 普通出牌不结算该牌原本的攻击、回复、状态、响应或 DIY 效果。
- 普通出牌不消耗、不会设置、也不会重置 `usedDIYThisCycle`。
- 普通出牌时，该实体牌进入 `discardPile` 一次，更新 `tableReference`，写入明确日志，正常推进一次行动，不进入 `responseWindow`，不创建新的 `CardInstance`。
- 有主行动效果的实体牌，在后续实现中必须区分“执行原有效果”和“仅普通出牌作为场面基准”两条路径。
- 元素牌、普通离子牌以及无即时主行动效果的实体牌，可以在 `tableReference` 为空或与当前 `tableReference` 关联时，作为无即时效果的普通出牌。
- MVP 0 新增规则概念 `tableReference`，表示最近一次 `mainAction` 中从手牌打出的实体牌。
- `tableReference` 至少记录 `cardInstanceId`、`definitionId`、显示名称、`playedBy`、`cycle`、`round`。
- `tableReference` 用于展示化学关联、未来技能、方程式与反应引用。
- `mainAction` 中的普通出牌会更新 `tableReference`。
- `mainAction` 中执行效果的实体手牌出牌也会更新 `tableReference`。
- `responseWindow`、`statusWindow` 中打出的牌不更新 `tableReference`。
- `virtual-diy` 与 `status` 伤害不更新 `tableReference`。
- `PASS_ACTION` 不更新 `tableReference`。
- 新实验周期开始时清空 `tableReference`。
- 关联规则：元素基准牌可接同一游戏分类的元素牌，或包含该元素的物质牌，或包含该元素的方程式牌；元素游戏分类使用 `metal` / `nonmetal` / `halogen`，当前 MVP 卡池中的 `O`、`C`、`S` 均为 `nonmetal`；离子/原子团、物质、方程式基准牌按原始规则书已有的“相关离子 / 含该离子物质 / 可反应物质 / 共享关键成分”等原则实现当前 MVP 卡池可表达的部分。
- “实验台起火”不是普通主牌堆实体牌；它是角色“手残党党委书记”的未来专属主动技能，不会从手牌打出，也不会作为 `tableReference`。
- 关联关系不是 `responseWindow`、`statusWindow`、主动 DIY、`PASS_ACTION` 的合法性门槛。
- 例：`O` 为基准时，`Na+` 不关联，不能普通出牌或执行效果；`O2`、`H2O`、`CO2`、`SO2` 等含 O 物质可出；当前同为 `nonmetal` 的 `C`、`S` 元素牌可出。
- “每周期一次万能自由出牌”或 UNO 强制变体不属于当前默认规则。

### 状态与响应

- `SO2_LEAK` 与 `FIRE` 是持续负面状态。
- 同名状态不叠加；已有同名状态时再次获得，只记录状态刷新日志。
- 不同状态可以同时存在，并按获得时间从早到晚处理。
- `SO2` 在 MVP 0 中只施加 `SO2_LEAK`，不造成即时伤害。
- `SO2` 施加状态时，不开启即时响应窗口；未来角色技能施加 `FIRE` 时也不应作为普通手牌出牌或更新 `tableReference`。
- 目标只能在自己下一次行动开始时的状态处理窗口中处理 `SO2_LEAK` 或 `FIRE`。
- `SO2_LEAK` 与 `FIRE` 在 MVP 0 中标记为“阻止回复”的负面状态。

### CO2

- 酸与碳酸盐响应生成的 CO2 在 MVP 0 中只写入操作日志。
- 该 CO2 不创建 `CardInstance`，不创建 token，也不能作为后续可用资源。
- `CO2` 执行灭火效果时，仅可在 `FIRE` 的 `statusWindow` 使用；`CO2` 也可在 `tableReference` 为空或与当前基准关联时作为实体牌走普通出牌路径，普通出牌时不触发灭火效果。
- 主动 DIY `C + O + O -> CO2` 不创建 CO2 卡牌；仅当行动玩家当前拥有 `FIRE` 时可用，并立即移除自己的 `FIRE`。
- 普通 `ion_co3` 与 `substance_na2co3` 都可以在 `responseWindow` 响应 acid DAMAGE。
- `ion_co3` 与 `substance_na2co3` 必须由 `pendingResponse.responderId` 使用，且不能响应 base DAMAGE。
- `ion_co3` 与 `substance_na2co3` 不能执行主行动效果，也不能处理 `FIRE` 或 `SO2_LEAK`；但可以走普通出牌路径作为场面基准。
- 成功响应时，取消本次酸性伤害；响应牌进入弃牌堆一次；日志明确写“生成 CO2”。
- 酸与碳酸盐生成 CO2 在 MVP 0 中仅为日志化反应结果，不触发灭火连锁。
- 若酸性伤害来自虚拟 DIY 攻击，响应成功时不重复弃置已经弃置过的组件。

### O2 自我回复

- `O2` 是可从牌库摸到的物质牌，不是通过 `O + O` 临时生成。
- 仅存活的 `activePlayer` 可在 `mainAction` 使用。
- `O2` 仅能对自己使用。
- 使用时弃置 1 张手牌中的 `O2`，回复 2 HP，且不超过自己的 `maxHp`。
- 使用 `O2` 不进入 `responseWindow`。
- 满 HP 时不能使用 `O2`。
- 当自己拥有 `SO2_LEAK` 或 `FIRE` 时不能使用 `O2`。
- `H2O` 执行灭火效果时，仅可在 `FIRE` 的 `statusWindow` 使用；`H2O` 也可在 `tableReference` 为空或与当前基准关联时作为实体牌走普通出牌路径，普通出牌时不触发灭火效果，且不回复 HP。
- `O + O -> O2` 主动 DIY 仍暂缓。

### H2O 主动 DIY

- `H+ + OH- -> H2O` 纳入 MVP 0 合法主动 DIY 配方。
- 只能由存活的 `activePlayer` 在 `mainAction` 使用。
- 仅当行动者自己拥有 `FIRE` 时可成功。
- 提交 1 张 `H+` 与 1 张 `OH-`；不需要 `targetPlayerId`。
- 两张组件进入弃牌堆一次，立即移除行动者自己的 `FIRE`。
- 不影响行动者自己的 `SO2_LEAK`，也不影响对方任何状态。
- 不创建 `H2O CardInstance`，不进入 `responseWindow`。
- 消耗本周期一次 `usedDIYThisCycle`，并正常推进一次行动。
- 自己没有 `FIRE` 时必须拒绝，且完全无副作用。
- 已有手牌 `H2O` 执行灭火效果时，仅可在 `FIRE` 的 `statusWindow` 中使用，不回复 HP，不可作为主动 DIY 结果卡牌；作为普通出牌时不触发灭火效果。
- 响应 DIY 继续关闭。
